# OpenCart Web 自动化测试计划

## 1. 测试目标

本项目目标是对 OpenCart 电商系统的核心 Web 流程进行自动化回归测试，验证基础业务流程是否可用。

重点覆盖：

1. 商品搜索；
2. 商品详情展示；
3. 加入购物车；
4. 购物车校验；
5. 登录失败提示。

---

## 2. 测试范围

### 2.1 本期包含

| 模块 | 测试内容 |
|---|---|
| 首页 | 页面可打开 |
| 搜索 | 搜索存在商品 |
| 搜索 | 搜索不存在商品 |
| 商品详情 | 校验商品名称 |
| 商品详情 | 校验商品价格 |
| 购物车 | 加入购物车 |
| 购物车 | 校验商品名称 |
| 购物车 | 校验商品数量 |
| 登录 | 错误账号密码登录提示 |

### 2.2 本期不包含

| 模块 | 原因 |
|---|---|
| 在线支付 | Demo 环境不适合执行真实支付 |
| 真实下单 | 需要稳定测试账号和测试数据 |
| 数据库校验 | 无数据库访问权限 |
| 性能测试 | 本项目聚焦 Web UI 自动化 |
| 安全测试 | 本项目聚焦功能回归测试 |
| 多浏览器兼容性 | 第一阶段只覆盖 Chrome |

---

## 3. 测试策略

本项目采用手工测试思路转自动化脚本的方式。

流程如下：

1. 分析电商核心业务流程；
2. 设计测试场景；
3. 编写测试用例；
4. 使用 Selenium 实现页面操作；
5. 使用 pytest 组织测试；
6. 使用 Page Object 封装页面；
7. 使用断言验证关键结果；
8. 使用 Allure 输出测试报告；
9. 失败时保存截图和日志；
10. 将代码和文档上传 GitHub。

---

## 4. 自动化框架设计

### 4.1 Page Object 分层

| 层级 | 作用 |
|---|---|
| `pages/` | 页面对象，封装元素定位和页面操作 |
| `tests/` | 测试用例，只描述业务流程和断言 |
| `docs/` | 测试计划、测试用例、缺陷记录 |
| `reports/` | 测试报告和截图 |

### 4.2 设计原则

1. 测试用例不直接写复杂元素定位；
2. 页面变化时优先修改 Page Object；
3. 每个测试用例只验证一个清晰目标；
4. 失败时提供可分析证据；
5. 保持代码结构适合维护和扩展。

---

## 5. 入口准则

开始执行测试前，需要满足：

1. WSL2 环境可用；
2. Python 虚拟环境已激活；
3. 项目依赖安装完成；
4. Chrome 可正常启动；
5. 被测网站可访问；
6. Git 仓库已初始化。

---

## 6. 出口准则

本阶段测试完成的标准：

1. 所有自动化用例可以运行；
2. 核心用例通过；
3. 失败时能生成截图；
4. pytest 日志正常生成；
5. Allure 报告可以生成；
6. 代码和文档已同步到 GitHub。

---

## 7. 风险与应对

| 风险 | 影响 | 应对方式 |
|---|---|---|
| Demo 网站结构变化 | 元素定位失败 | 修改 Page Object 中的定位器 |
| 网络不稳定 | 测试偶发失败 | 重新执行，必要时增加等待 |
| Cloudflare 拦截 | 页面无法访问 | 不使用官方 demo.opencart.com |
| Chrome 版本变化 | 浏览器启动失败 | 更新 Chrome 或 Selenium |
| 测试数据变化 | 断言失败 | 使用稳定商品如 iPhone |
| 加入购物车成功提示加载不稳定 | 用例误判失败 | 不只依赖 `.alert-success`，同时校验购物车数量变化和购物车页面最终商品数据 |
